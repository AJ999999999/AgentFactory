# What the first real runs showed (Windows, Copilot CLI 1.0.105, Claude Code 2.1.314, Codex CLI 0.166.0, pi 1.4.0)

- **Copilot has one model on this plan.** Its router reports only `gpt-6-luna`, and `--model` refuses every name, that one included. So `model-a` and `model-c` stay empty (Copilot's default), and `model-b`, the judges, is `claude:opus`.
- **`copilot -p --output-format json` streams events.** The harness reads them for the log, the reply, the model and premium requests. The GitHub MCP server's instructions are in that stream, so capacity is read only from error events and stderr.
- **Copilot's npm loader starts a native `copilot.exe` as a child.** Stopping a turn kills the tree (taskkill /T).
- **Claude Code streams `rate_limit_event` with an exact reset time.** It also warns when the plan is near its weekly limit; the turn log shows that.
- **Codex's sandbox needs `windows.sandbox="elevated"` passed back in.** `--ignore-user-config` drops it, and without it `workspace-write` silently acts as read-only on Windows. Its sandbox keeps `.git` read-only, so commits fail, and stopping a turn kills the sandboxed commands too.
- **An example's placeholder was sent as an answer, and couldn't be taken back.** The answer command, shown with `--note "..."`, was run as it was. That marked a profile question done with `...` as the note, and that note is all the build agents are told about the person. The build would have started on it at the loop's next check, and an answer couldn't be changed, only paused around. Answers now refuse a note with no words in it, and `correct <ask> --note` replaces what a note says. The choice stands, and so does what it already did.
- **The owner's Codex and pi default to a custom provider** (`magpie`, `workbuddy-ai/deepseek-v4.1-flash`, a local gateway). pi keeps it. Codex turns ignore the user's config, so `cli.codex.userProvider` reads just the provider section and default model from it, with an inline token handed over in `AF_CODEX_PROVIDER_TOKEN`. Without that, Codex fell back to OpenAI on a ChatGPT plan whose Codex allowance was spent until November 17.
- **pi turns load the gate, and it holds.** It refused an out-of-scope write, `git push`, `git status; echo hi` and a read of `C:\Windows\win.ini`, and the model carried on within its grant.
- **Build agents called a test someone else broke "not mine" and said they were done.** A levels turn, which ran only the levels check, changed the levels, and two of the core's tests began to fail. Each of three tries at the next build todo saw those failures, reported done with them in its note, and was thrown away by the game's test check, until the todo ran out of tries. The packet then didn't name the checks, and a retry was told only "validation_failed". Now it names the checks, says a failure in code the agent didn't write still counts, and tells a retry why its last try was thrown away. The levels agent had proposed the right follow-up: make all five levels playable and update the tests. It wrote the paths with Windows backslashes (`game\game.js`), so the follow-up was dropped as out of scope. A proposed todo's paths now take either slash.
- **The owner's personal Copilot skills took over turns.** 14 of 17 eval turns loaded one; `poteto-core` demanded "ownership confirmation" and refused to edit. Copilot turns now run with `--no-custom-instructions --excluded-tools skill`. A probe confirmed it can't load a skill then. Don't use `--dynamic-retrieval skills=off`: it persists into the owner's settings.
- **A world module outside this repo couldn't load on Windows.** `open --world <file>` passed the absolute path (`C:\...`) to `import()`, which reads it as a URL with the scheme `c:`. The smoke runs used only the built-in `case:` worlds, so the first private engagement was the first to hit it. The command line now imports it as a `file://` URL.
- **Copilot asks for every website separately, even with `web_fetch` allowed.** A headless turn can't answer, so a research turn had every page refused ("no interactive user response was available") and cited pages it had never read. Seats with `web:read` now also get `--allow-all-urls`. The tool's name, `web_fetch`, is confirmed from the event stream. Copilot 1.0.105 names a tool only when the call starts, so the turn log now matches a failure back to that name instead of saying "tool".
- **Shells run by Claude Code may not reach the web.** Its sandbox resolves only some hosts (GitHub, not example.com), so a turn ticked from there can't read pages even when allowed. The scheduled task runs outside it.
- **Agents proposed a `job` without a spec, for a pilot only the parent could run.** The validator dropped it. The prompt now says which kinds need what, who an action can go to, and to cite only what was read.
- **The scheduled loop's crash log filled with routine events.** The harness wrote each event (a wake, a lease, a merge) to stderr, which the task sends to `loop.err.log`, and Windows PowerShell turned every line into a six-line error. With `--log`, the loop now writes them to its own log, which rotates, and stderr is left for crashes.
- **A seeded app can hide the harness's own log.** The second private engagement seeded an existing Python app whose `.gitignore` ignored `.agents/` and every `*.json`, which is where the event log lives. It ran only after exceptions were added by hand (docs/next/140).
- **Builder turns need a test command they're allowed to run.** Seats may only run `npm test`, so a Python project needed a `package.json` whose `test` runs pytest through the owner's venv. Turns weren't told this and tried `python` directly. Every turn is now told the commands its seat may run, read from the grant its CLI enforces, and that anything else is refused. Codex, which can't limit commands, is told what its sandbox allows instead. Whether a seat can run the project's tests at all is still unchecked (docs/next/140).
- **Turns re-proposed the planned next steps** as new todos in lanes of their own, each staffed by a new probation role, until the packet listed the goal's open work (#28). The partner had no way to drop them until #27.
- **All steps done and green is not the same as working.** Every todo finished and the review agreed with the rules, but the first run on real data showed the result almost never acted (docs/next/200).
